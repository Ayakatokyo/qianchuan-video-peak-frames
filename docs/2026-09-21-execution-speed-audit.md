检查日期：2026-09-21。基线：`fc42668`，分支 `codex/migrate-direct-material-data`。本轮只修改本仓库技能入口、分析读取/审阅辅助程序和回归测试；未执行线上 RPA，未发布运行包，未覆盖历史客户数据。

## 结论

确有不必要的模型往返，但不能把慢的原因直接归为“脚本文件太多”，也不能据 Bash 汇总耗时排除后台采集、视频处理或运行环境问题。本次优先消除重复前置检查、素材内拆批、重复引用输出和机械复核抄写，保留逐图观察、证据覆盖、哈希绑定和最终校验。

## 脚本数量与必要步骤

`scripts/` 有 36 个受 Git 管理的 Python 文件，只有 5 个有直接 CLI 入口，31 个是内部模块。默认业务流程只需操作 `run_standard_analysis.py`；另外 4 个入口用于独立取数、底层处理或修复。把模块合成一个大文件不会减少模型调用，也没有证据证明文件数量导致这次分钟级延迟。本轮没有新增生产脚本或新的子命令。

| 步骤 | 处理 |
|---|---|
| prepare 前再单独 import 依赖、detail/schema/list-accounts/validate | 表单参数齐全时删除这轮人工检查；正式入口已有依赖、授权和动态参数校验。独立诊断场景保留底层命令。 |
| 一条素材拆为 4＋2 两轮观察与提交 | 新账本默认最多 6 个唯一 SHA，同素材通常一次 checkpoint；旧 4/6 帧账本按原计划续接，完整覆盖不变。 |
| checkpoint 后再次查询下一批 | 直接使用 checkpoint 返回的下一批；中断恢复时才单独查询。 |
| 每个任务重复读事实、骨架、完整引用表 | 默认 `--section facts`；骨架 contract 和合法引用 references 按需读取。旧调用的 all 视图保留。 |
| 长数组每条值重复携带路径 | 连续数组段使用 start/items，无损恢复原顺序；任务页完整 stdout 上限 8000 字节，保留结构缩进。 |
| 每读一页构建全部任务 | 验证完整输入后，只构建所请求的任务；输入和 JPEG 哈希校验保留。分页实现也纳入读取绑定。 |
| 模型手抄上千条复核引用 | `validate-analysis --review-template <新文件>` 同次生成精确引用、绑定哈希和说明，decision/reason 留空；当前模型核对全部证据后填写判断，模板不能直接通过门禁。已有文件不覆盖。 |
| 填完复核后 validate 成功，再立即 finalize | 可直接 finalize 携带复核文件；其内部仍重新执行同一完整门禁，失败不会生成报告。不缓存或跳过质量判断。 |

不删除的步骤：真实 JPEG 理解、逐素材商业结论、片段引用预检、完整帧覆盖、内容复核、最终资源与交付校验。减少这些步骤可能缩短时间，但会改变用户要求的分析范围或可靠性。

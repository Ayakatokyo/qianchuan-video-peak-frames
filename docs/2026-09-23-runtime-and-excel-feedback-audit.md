## 修改

### 1. Excel 恢复为标准交付，完成后支持补齐

- 标准 `finalize` 默认包含 XLSX，保留 `--include-workbook` 兼容；`--skip-workbook` 才显式省略，ZIP 仍需 `--archive`。底层兼容渲染函数保留原有 opt-in 默认，正常技能流程使用统一 CLI。
- complete 可以重新进入 finalize，但仍核验候选、事实、图片账本、内容复核和锁。预检失败不把已交付摘要改成 failed；不允许绕过 AI 门禁或重复 RPA。
- Excel 选项不再参与报告事实投影的哈希；同版本、同输入时补 Excel 复用 reportData，只刷新 workbook/HTML，并使旧归档收据失效。升级源码会使旧收据失效，首次升级补建可能重建投影，不能承诺跨版本零重建。
- 交付门禁核对 HTML 数据中的 `highlightExportHref` 目标文件；坏图片导出改为显式失败，不再静默返回 None 并隐藏入口。正常导出仍验证 XLSX ZIP、工作表、图片锚点数量。
- 模板中的按钮初始就带 hidden，由 JS 根据数据启用；**不能只 grep hidden 判断功能成败**，须核对嵌入数据、目标文件与浏览器操作。

### 2. 降低报告峰值内存

- JSON 原子写出使用流式 `json.dump`，不再先构造整份缩进字符串再写文件。
- 报告内部自有数据原地更新视频路径，避免复制整份报告；公共辅助函数仍默认不修改传入对象。
- 渲染后只留下小型复核/构建收据，先释放完整报告对象再重新核验事实和落盘文件；收口校验也在解析 HTML 数据前释放磁盘报告对象。
- 保留现有事实、报告字段和质量门禁，不通过删事实、降帧数或硬编码分配器参数省内存。

### 3. 有状态的有界等待

- 新增 `status --wait-seconds 60`（0–60 秒），最多每 5 秒检查一次，离开 wait 立即返回；只读，不提交/恢复任务。
- 优先使用运行面已支持的持久执行会话。setsid 仅在确认跨调用存活时使用，不能保证进程避开容器回收；不杜撰平台工具或生命周期接口。
- 终态/失联由 status.nextAction 决定下一步，不再固定 sleep 240/280/1500 秒。此改动减少中断发现延迟，**不会修复宿主回收进程本身**。

### 4. 错误前移，减少整份候选返工

- contract 明示素材 decision 枚举、customClassification 顶层位置、分类覆盖范围、keywordRefs 必须逐字匹配原词并绑定词内脚本证据。
- `check-analysis-part` 对单个合并片段也共享一次输入快照，按素材/分类/关键词独立收集错误；能同时返回多个问题，不需先组装、整体验证才发现下一类。
- 关键词校验复用正式内容契约；最终结构和人工内容复核仍必需，预检不会标记内容已审阅。
- 同步一个上版已存在的 Prompt 测试漂移：测试改为当前“一个核心判断和一个优先验证动作”，没有向运行 Prompt 加回“三项判断”的冗长要求。
